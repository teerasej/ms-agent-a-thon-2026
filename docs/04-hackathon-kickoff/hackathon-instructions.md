# Hackathon Instructions

สร้าง Agent ที่ช่วยแก้ปัญหาซึ่งเกิดขึ้นจริงและเกิดซ้ำในงานของทีม ให้ความสำคัญกับ Use case ที่ทำสำเร็จได้ในเวลาที่มี แม้ช่วยประหยัดเวลาเพียงเล็กน้อย แต่เกิดประโยชน์บ่อยครั้งก็มีคุณค่า

## 1. Form your team

ตั้งชื่อทีมและแบ่งหน้าที่ดังนี้ สมาชิกหนึ่งคนสามารถรับมากกว่าหนึ่งหน้าที่ได้

- **Problem owner:** อธิบายปัญหาและวิธีทำงานปัจจุบัน
- **Builder:** สร้างหรือปรับ Agent
- **Tester:** ทดลองคำถามปกติและกรณีนอกขอบเขต
- **Presenter:** เตรียม Hack Pack และนำเสนอ

## 2. Choose one use case

เลือกงานที่มีผู้ใช้ชัดเจน เกิดขึ้นจริง และทำซ้ำบ่อย ตอบคำถามสั้น ๆ ต่อไปนี้:

1. ใครพบปัญหานี้
2. วันนี้เขาทำงานนี้อย่างไร
3. Agent จะช่วยตรงขั้นตอนใด
4. มนุษย์ยังต้องตรวจหรือตัดสินใจเรื่องใด

Slides สำหรับ Brainstorm ใน Hack Pack เป็นส่วนเสริม ไม่จำเป็นต้องนำเสนอ

## 3. Complete the two required slides

### Required slide 1: Business case

เติมข้อมูลต่อไปนี้ให้คนที่ไม่รู้จักงานของทีมเข้าใจได้:

- **Problem Statement:** ปัญหาและวิธีทำงานปัจจุบัน
- **Solution:** Agent จะช่วยอย่างไร
- **Personas:** ใครเป็นผู้ใช้
- **Example Use Case:** ตัวอย่างคำถามหรืองานที่ Agent รับผิดชอบ
- **KPIs & Impact:** จะวัดผลอย่างไร

กำกับตัวเลขทุกตัวว่าเป็นอย่างใดอย่างหนึ่ง:

- **Measured:** มีข้อมูลจริงรองรับ
- **Estimate:** เป็นค่าประมาณที่ต้องพิสูจน์
- **Target:** เป็นเป้าหมายที่ทีมต้องการทดสอบ

### Required slide 2: Agent design

ระบุ:

- Agent name และ Agent type
- Agent description
- Agent instructions
- Knowledge sources
- Tools หรือ Capabilities
- Triggers และ Actions เฉพาะ Agent ที่สร้างด้วย Copilot Studio และใช้ความสามารถเหล่านี้จริง

## 4. Build and test

สร้าง Agent ด้วย Microsoft 365 Copilot หรือ Copilot Studio หากสร้าง Prototype ไม่ทัน สามารถสร้างวิดีโอสั้นที่อธิบาย Agent และประสบการณ์ใช้งานที่ตั้งใจไว้

ทดสอบอย่างน้อยสองกรณี:

1. **Normal request:** งานหลักที่ Agent ต้องทำได้
2. **Boundary case:** คำถามที่ข้อมูลไม่พอ ไม่มีสิทธิ์ หรืออยู่นอกขอบเขต

บันทึกสิ่งที่ทำงานได้และข้อจำกัดจริง ห้ามนำเสนอ Mockup หรือวิดีโอเหมือนเป็นระบบที่ทำงานแล้ว

## 5. Prepare the five-minute presentation

| เวลา | เนื้อหา |
| --- | --- |
| 1 นาที | ปัญหา ผู้ใช้ และวิธีทำงานปัจจุบัน |
| 2 นาที | Solution และ Demo หรือวิดีโอ |
| 1 นาที | Knowledge, Tools และสิ่งที่มนุษย์ต้องตรวจ |
| 1 นาที | Expected impact, หลักฐานที่มี และขั้นตอนถัดไป |

ซ้อมการนำเสนอหนึ่งครั้ง และเตรียมไฟล์ให้พร้อมก่อน Team Presentations เริ่มเวลา 3:15 PM ส่งงานผ่านช่องทางที่วิทยากรประกาศในห้อง

## Completed example

Slides ท้าย Hack Pack แสดงตัวอย่าง Customer Service Agent สำหรับ Root Cause Analysis ให้ดูวิธีเชื่อม Problem, Process, Personas, Knowledge และ Actions เข้าด้วยกัน ตัวเลข KPI และผลประหยัดในตัวอย่างมีไว้แสดงรูปแบบเท่านั้น ห้ามนำไปใช้เป็นหลักฐานของทีม

## Final checklist

- [ ] ปัญหาเกิดขึ้นจริงและมีผู้ใช้ชัดเจน
- [ ] Agent มีหน้าที่เดียวที่อธิบายได้ง่าย
- [ ] Knowledge และ Tools เชื่อมกับงานที่ Agent ต้องทำ
- [ ] ทดสอบ Normal request และ Boundary case แล้ว
- [ ] แยก Measured, Estimate และ Target ชัดเจน
- [ ] Demo หรือวิดีโอพร้อมใช้งาน
- [ ] Required slides ทั้งสองหน้าเสร็จแล้ว
- [ ] การนำเสนอไม่เกินห้านาที
